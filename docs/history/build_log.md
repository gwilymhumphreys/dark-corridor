# Dark Corridor — Build Log (chronological record)

> The dated record of what got built, in order — moved out of the decision log
> (which now holds decisions only). **Current** status lives in
> [`../handoff.md`](../handoff.md); this file is the history. The per-phase plans
> in this directory are the detailed step-by-steps each entry followed.

- **Phase 1 — the combat spine — is built and green.** The build-prep decisions (#23–25), then Steps 1–5 of [`phase1_plan.md`](phase1_plan.md): `Timekeeper` · `Actor` · `StatusManager` · `Item` · `CombatManager` + a minimal **opaque** VFX wall + the `combat_sandbox` host. **45 GUT tests pass headless on 4.6; the feel gate passed.** Code now lives in `src/combat/`, `src/content/`, `src/autoloads/status_manager.gd`, `src/data/balance.gd` (placeholder tuning), `src/vfx/`, `src/scenes/combat/`, `tests/`. GUT is vendored in `addons/gut/`.

- **Phase 2 — autotest scaffolding — is built and green** (2026-06-05): the Mode/Driver/Logger trio + `AutoTestStuckDetector` in `src/autotest/` (dedicated `autotest.tscn`) drive ONE deterministic headless fight to a verdict via `CombatManager.sim_step()` — flags, forced nosave/notutorial, game-time `--timeout` + `--wall-timeout` + stuck detection, damage-by-family logging + a markdown report, exit `0` (resolved) / `1` (stuck/timeout). `--seed` / `--speed` are plumbed-but-inert until the run RNG (Phase 3). A Phase-1 review pass first hardened the spine (heal guard, Delivery pruning, seq_id doc).

- **Phase 3 — the run loop — is built and green** (2026-06-05, [`phase3_plan.md`](phase3_plan.md)): `Save` (autoload, JSON snapshot, atomic, no migration) + minimal `Relic` (combat-start status) + `Draft` (autoload, seeded 1-of-3) + `Encounter` (fight/rest, in `src/run/`) + `RunManager` (map, run-state, sequencing, HP-economy, snapshot/rehydrate, in `src/run/`) + `GameManagerAutoload` (`Game`: phase machine + run lifecycle). The autotest now drives a whole headless descent (`run_full`) — draft → fight → advance → win, deterministic by `--seed` (now live), with quit/resume. New autoloads `Save` / `Draft` / `Game`; new dir `src/run/`.

- **Fast-follow done (2026-06-06):** the **enchant** (Whetstone, scale-a-value on the board) + **consumable** (Healing Draught, thrown self-heal via `CombatManager.throw_consumable`) categories — so all three content categories prove their path end-to-end in the run + autotest. Also resolved **decision #26** (statuses are combat-scoped; persistence = relics/enchants) and fixed the **`Actor`↔`Item` RefCounted leak** (`Actor.dissolve()` at discard) + made status advancement uniform across actors and items. **112 GUT tests pass headless on 4.6.**

- **Phase 4 — real UI / the run screen — is built and green** (2026-06-06, [`phase4_plan.md`](phase4_plan.md)): the presentation tree (`main.tscn` → `MainController` → title / run / outcome screens) + the **real-time seam** (the run screen drives `CombatManager.tick` each physics frame; the logic tree stays *out* of the scene tree — the autotest path is byte-identical) + the **framed** combat view (corridor + thorn-demon **occupant** top-right via `CorridorScaled.axis_scale`, player left, board strips / HP / potions, the VFX wall) + slow-mo-on-hover + the run-screen **FSM** (approach → fight → draft → advance → win/death) + the **draft overlay** + the **map strip** + the **corridor approach** (the enemy scales from depth). New dirs `src/scenes/screens/` + `src/scenes/combat/` (the view); `main_scene` flipped to `main.tscn`. Full doc: [`systems/run_screen.md`](../systems/run_screen.md). Deviations: the `RunManager.advancing` signal was unneeded (the run screen orchestrates the advance + approach directly, keeping `RunManager` presentation-free); one parameterized `outcome_screen.tscn` instead of two. **126 GUT tests pass headless on 4.6.** Two follow-ups done (128 tests): the **potion-throw UI** (clickable slots → `RunManager.throw_potion`) + the **localization POT pipeline** (`tools/extract_pot.gd` → `locale/`, registered in `project.godot`; [`localization.md`](../systems/localization.md)).

The interface look shader passes extra brightness through its effects. Settings in the interface look panel's Glow section and files; `--glow-demo=` for screenshots. A delegation of this to the local model stalled with no output while another session's run was using the model, so it was built by hand.

- **[Screen sections](../systems/ui_layout.md#screen-sections) (2026-09-17, 489 tests):** the run screen is split into four sections matching the paper folds: corridor top left, potions and items top right, portraits lower left, and map, gold and battle-speed button lower right. The run screen owns one `ScreenSections` and the combat view places its parts in it. The F5 print panel's Layout group replaces the corridor margin with a padding (owner: 20px to start) and split across / split down sliders; moving them reflows the item columns and resizes the portraits to fit.

- **[Look presets](../systems/look_presets.md) and one tabbed debug panel (2026-09-17, 560 tests):** the four debug panels are now one panel with a preset bar and four tabs (Palettes F1, Corridor F2, Interface F3, Print F5); a key opens its tab, switches to it, or closes the panel when its tab is showing. A preset holds the whole look in four parts, each written and read by the code that owns it (`write_palettes`, `write_corridor_look`, `InterfaceLook.write_look`, `PrintLook.write_print_look`), and replaces look files, interface looks, print looks and palette combos. The font is now saved too. `assets/presets/default.cfg` loads at start-up in every run; Make default copies the old default into `assets/presets/history/` first. Each tab can take its part from another preset. The 15 corridor looks and the `gothic_bit` palette combo became presets carrying the old print default, which alone became the default preset; a script checked every old value carried over. `--preset=` replaces `--look=`, `--print-look=`, `--interface-look=` and `--palette-combo=`; the start-up combo choice in `user://` is gone. The later steps (release builds, player settings) are in `docs/plans/look_settings_for_players.md`.

- **Palette rows moved into the Corridor and Interface tabs (2026-09-17, 562 tests):** the Palettes tab (F1) is gone. The world palette and colour matching are rows at the top of the Corridor tab, whose Dithering section header was already the world clamp's dithering switch. The interface palette, portrait palette and font are rows at the top of the Interface tab. Presets have three parts: the corridor part gains a `corridor_palette` section and the interface part an `interface_palette` section, so "Take this part from" brings the palette with the look it was tuned for. The 16 preset files were rewritten to match. The picture wear and panel wear section headings now say what they apply to (images, or item borders and other panels).

- **[Background wear](../systems/background_wear.md) moved to its own tab (2026-09-18, 569 tests):** the debug panel's tabs now start at F1 — Corridor F1, Interface F2, Print F3 — and background wear has a fourth tab of its own, Background F4 (`src/debug/background_panel.*`). It is also a fourth preset part, so it can be taken from another preset without touching the print part; `PrintLook` gained `write_background_look`, `read_background_look` and `reset_background_look`, and the `print_background` section stayed where it was, so no preset file changed. The Print tab now holds Layout, the border, the wear over the corridor and panel wear. The [print border](../systems/print_frame.md) is drawn in the background wear's colours (`UI_BACKGROUND_WEAR` for the line, `UI_BACKGROUND_WEAR_LIGHT` for its rubbed spots) instead of its own red, so `Colours.UI_BORDER` and the `ui border` entry in the four interface palettes are gone.

- **A soundtrack, and silent test runs ([audio](../systems/audio.md), 2026-09-18, 495 tests):** three dungeon synth packs by arnocyreus — Lordran Tapes, Outrider's Oath and Bonfires — are in the game, credited in the new [asset_credits.md](../design/asset_credits.md) (the project had no attribution page before; the art packs and the font have rows there with their sources still to fill in). Each track was converted from the supplied WAV to `.ogg` (libvorbis, quality 5) into `assets/music/` — 24 tracks, about 73MB — where `MusicManager` picks them up and shuffles them with no code change. Lordran Tapes and Outrider's Oath also ship loop versions; the crossfade already blends a track out, so the full-length versions are the ones in the project. The default volume for all three audio keys is now 0.5, down from separate per-bus values. A run started with `--autotest` or `--shot` is silent: `Prefs` mutes the Master bus at boot without touching the stored levels, and `MusicManager` skips loading the folder, so the autotest no longer decodes the whole music folder on every run. `MusicManager` also skips loading under the headless dummy audio driver, which never releases a playback and so reported the playing track as leaked at exit — the same driver behaviour already noted for `SfxManager`. Confirmed against a real audio driver: 15 tracks load and play on the Music bus in a normal run, nothing loads or plays under either flag, and neither a windowed autotest nor a `--shot` capture leaks.

- **The prototype content is gone (2026-09-18, 571 tests):** the Wanderer and Duelist placeholder characters, the Rusted Blade, Iron Guard and the three leather shield pieces, and `DraftPool` are deleted. `CharacterCatalog.ids()` is now the Fleshmancer then the Spore Druid, and `DEFAULT` — the title-screen autostart, the save-resume fallback and the autotest baseline — is the Fleshmancer. Venom Fang stays in the catalog, in no pool, as the only poison content and therefore the only thing that can fire Spite Ward's trigger; Spite Ward, Hex Bolt and Sunder stay unpooled as before. `WEAPON_COOLDOWN` / `WEAPON_DAMAGE` are renamed `ENEMY_CLAW_*` and `ARMOR_*` to `SPITE_WARD_*`, after the items that still use them; the `LEATHER_*` constants are gone. Combat, UI and event tests no longer spawn authored cards: a new `tests/fixtures/fixture_items.gd` builds an attack, a shield, a poison applier and an enemy-named attack, carrying the deleted prototypes' numbers so no timing or damage assertion changed meaning. Draft tests draw from the Fleshmancer's pool, because `Draft.draw` works on catalog ids. Two consequences of the deletion, both content work for the owner: no character has a starting relic, potion or enchant, so those three paths are unreachable in play (the tests grant them explicitly), and the default descent on seed 3 now ends in a death where the Wanderer's build won, so the autotest resume test asserts the run finishes rather than wins.

  Two problems surfaced while doing it. `tests/combat/test_combat_manager.gd` had been failing to
  parse, so GUT skipped the whole file (a warning, not a failure) and still reported a clean run —
  the suite count went from 495 to 571 once it loaded again, so check the script count, not just
  the pass line. And the default autotest run logged repeated script errors from firing an
  ownerless item: `sim_step` collects the step's cooldown crossings before any of them fires, and
  firing one item can remove another that already crossed (own-board consume eats board items, a
  decay use-status can empty), leaving a dissolved item to fire with a null owner. It only showed
  up in a played run once the Fleshmancer became the default character, since its Chunks of Flesh
  are both created and eaten. `CombatManager.sim_step` now skips a crossed item whose owner has
  gone, with a regression test.

- **[Control feedback](../systems/control_feedback.md), and the theme off the pack art (2026-09-19, 602 tests):** every Button state now draws the same flat `PaletteStyleBox` fill on the new `Colours.UI_BUTTON`, Godot's built-in tooltip popup moved onto the flat framed style, and the `CheckBox` icon entries and the unused `WideButton` variation are gone, so the theme references none of `assets/ui/*.png` (the cursors in that folder are unaffected). Hover, selection and press are drawn instead by `control_highlight.gdshaderinc`, which `panel_wear.gdshader` includes and applies after the wear: the highlight therefore rides panel wear's material and its per-control canvas item, behind the control's text and already carrying the panel's rectangle. A first attempt with a separate canvas item drew the wash over the text. Each control carries `hover`, `selected`, `press`, `bloom` and `fill_shown` as instance uniforms; a plain button lights its whole body, anything whose body is a picture takes the border only. `UIJuice` drives it and adds a small drop to the press squash and an ink pulse on release, and tweens the button's font colour with its own `text_hover` / `text_press` amounts. Board item cells have no mouse events of their own, so `combat_view_framed.gd` sets `ItemCell.hovered` from the tooltip hover poll. New autoload `ControlFeedback`, a fifth debug tab (Feedback, F5) and a fifth preset part (`control_highlight`, `control_settings`), written into the 22 saved presets so they still compare equal, plus `--feedback-set=`, `--feedback-panel` and `--feedback-demo=` for screenshots. Four new `Colours` entries (`UI_BUTTON`, `UI_BUTTON_LIGHT`, `UI_TEXT_BUTTON_DARK`, `UI_HIGHLIGHT`) are in all four interface palettes.

- **Board grid and fitted item cells (2026-09-22, 716 tests):** the player's items sit on a pencil grid (`board_grid.gdshader`, drawn through `PrintLook.grid_material`, with a Board Grid group in the Print tab), one square per cell, and each cell is set down slightly askew like a cardboard token (`token_tilt`, `token_shift` in the Print tab's Layout group). `CombatViewFramed._fit_board` shrinks every cell together so the whole board fits the items section, since a run ends on about 41 items and about 30 fit at full size. Building it found an existing bug: from about 21 board items the extra cells, the player portrait and the speed button drew blank, because every node drawn through `interface_look.gdshader` took 16 of the compatibility renderer's 4096 instance uniform slots for the portraits' `picture_zoom`. The shader now lives in `interface_look.gdshaderinc`, and only `interface_portrait.gdshader` (on the new `InterfaceLook.portrait_material`, used by the three breathing portraits) has that uniform. New screenshot hook `--board-items N`.

- **Token fill and a Tokens tab (2026-09-22):** the token settings moved from the Print tab's Layout group to their own debug tab, Tokens (F7), in Placement, Shadow, Fill and Portraits sections.
