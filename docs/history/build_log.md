# Dark Corridor — Build Log (chronological record)

> The dated record of what got built, in order — moved out of the decision log
> (which now holds decisions only). **Current** status lives in
> [`../handoff.md`](../handoff.md); this file is the history. The per-phase plans
> in this directory are the detailed step-by-steps each entry followed.

- **Phase 1 — the combat spine — is built and green.** The build-prep decisions (#23–25), then Steps 1–5 of [`phase1_plan.md`](phase1_plan.md): `Timekeeper` · `Actor` · `StatusManager` · `Item` · `CombatManager` + a minimal **opaque** VFX wall + the `combat_sandbox` host. **45 GUT tests pass headless on 4.6; the feel gate passed.** Code now lives in `src/combat/`, `src/content/`, `src/autoloads/status_manager.gd`, `src/data/balance.gd` (placeholder tuning), `src/vfx/`, `src/scenes/combat/`, `tests/`. GUT is vendored in `addons/gut/`.

- **Phase 2 — autotest scaffolding — is built and green** (2026-06-05): the Mode/Driver/Logger trio + `AutoTestStuckDetector` in `src/autotest/` (dedicated `autotest.tscn`) drive ONE deterministic headless fight to a verdict via `CombatManager.sim_step()` — flags, forced nosave/notutorial, game-time `--timeout` + `--wall-timeout` + stuck detection, damage-by-family logging + a markdown report, exit `0` (resolved) / `1` (stuck/timeout). `--seed` / `--speed` are plumbed-but-inert until the run RNG (Phase 3). A Phase-1 review pass first hardened the spine (heal guard, Delivery pruning, seq_id doc).

- **Phase 3 — the run loop — is built and green** (2026-06-05, [`phase3_plan.md`](phase3_plan.md)): `Save` (autoload, JSON snapshot, atomic, no migration) + minimal `Relic` (combat-start status) + `Draft` (autoload, seeded 1-of-3) + `Encounter` (fight/rest, in `src/run/`) + `RunManager` (map, run-state, sequencing, HP-economy, snapshot/rehydrate, in `src/run/`) + `GameManagerAutoload` (`Game`: phase machine + run lifecycle). The autotest now drives a whole headless descent (`run_full`) — draft → fight → advance → win, deterministic by `--seed` (now live), with quit/resume. New autoloads `Save` / `Draft` / `Game`; new dir `src/run/`.

- **Fast-follow done (2026-06-06):** the **enchant** (Whetstone, scale-a-value on the board) + **consumable** (Healing Draught, thrown self-heal via `CombatManager.throw_consumable`) categories — so all three content categories prove their path end-to-end in the run + autotest. Also resolved **decision #26** (statuses are combat-scoped; persistence = relics/enchants) and fixed the **`Actor`↔`Item` RefCounted leak** (`Actor.dissolve()` at discard) + made status advancement uniform across actors and items. **112 GUT tests pass headless on 4.6.**

- **Phase 4 — real UI / the run screen — is built and green** (2026-06-06, [`phase4_plan.md`](phase4_plan.md)): the presentation tree (`main.tscn` → `MainController` → title / run / outcome screens) + the **real-time seam** (the run screen drives `CombatManager.tick` each physics frame; the logic tree stays *out* of the scene tree — the autotest path is byte-identical) + the **framed** combat view (corridor + thorn-demon **occupant** top-right via `CorridorScaled.axis_scale`, player left, board strips / HP / potions, the VFX wall) + slow-mo-on-hover + the run-screen **FSM** (approach → fight → draft → advance → win/death) + the **draft overlay** + the **map strip** + the **corridor approach** (the enemy scales from depth). New dirs `src/scenes/screens/` + `src/scenes/combat/` (the view); `main_scene` flipped to `main.tscn`. Full doc: [`systems/run_screen.md`](../systems/run_screen.md). Deviations: the `RunManager.advancing` signal was unneeded (the run screen orchestrates the advance + approach directly, keeping `RunManager` presentation-free); one parameterized `outcome_screen.tscn` instead of two. **126 GUT tests pass headless on 4.6.** Two follow-ups done (128 tests): the **potion-throw UI** (clickable slots → `RunManager.throw_potion`) + the **localization POT pipeline** (`tools/extract_pot.gd` → `locale/`, registered in `project.godot`; [`localization.md`](../systems/localization.md)).

- **Phase 5 — the `tune` machinery — is built** (2026-06-06, [`phase5_plan.md`](phase5_plan.md), 139 tests): seeded board-aware **draft strategies** (`--strategy` live) + a **per-encounter / per-item report** (durations vs window, HP attrition, item fires + damage + trap-pick flags) — the two things the `tune` workflow needs.

- **Non-content backlog item — settings/pause + battle-speed — built** (2026-06-06, 153 tests): the **×1/×2/×3 battle-speed dial** (a `Game` session preference + an always-visible HUD toggle, applied to each fight's `Timekeeper` base scale) + in-run **pause** (a run-screen gate, **not** a `Game` phase) with a pause menu (Resume / Quit-to-menu, the save preserved so Title's Resume re-enters the beat); also **resolved the timescale replace-vs-multiply open → replace** (absolute slow-mo, independent of the dial).

- **Non-content backlog item — DoT per-applier attribution — done** (2026-06-06, 158 tests): the tune report's damage-by-family + item-contribution table now credit poison-tick damage to the **item that applied it** (a pre-step status snapshot reads `Status.source`), so Venom Fang shows its real poison damage instead of a generic "Poison" lump reading 0 — sharpening what `tune` reads (in `src/autotest/`).

- **Run structure + reward routing + status-build engine seams — built (2026-06-07):** the **multi-act run** (`RunMap` = 3 acts × 15 beats; act-end bosses, a fixed midpoint relic + a per-act rest, the rest **CHOICE** beats) with the **choice layer** (`has_pending_choice` / `pending_choice` / `pick_path`, drawing 2-3 seeded candidates), a **two-tier choice UI** (`choice_overlay`) + a placeholder **Event** type (`event_overlay` / `pick_event_option`, prose + binary outcome), the run-screen FSM gaining CHOOSING / EVENTING states, and the **HP economy** (between-act full heal, per-act rest) (#1, #16); **reward routing** — a relic on the **RELIC** reward + a relic-and-draft on the new **ELITE** reward, drawn from `RelicCatalog.REWARD_POOL` on the run RNG (deterministic / resume-stable), plus a relic `MAX_HP_BONUS` shape (#2); **per-fight RNG** (`_combat_seed_for` = run seed + encounter index) + a random-targeting item exercising the derived per-fight stream (#14, #20); the **spore-engine seams** Cap 1+2 ([`spore_engine.md`](../systems/spore_engine.md)) — `StatusManager.consume(target, type, amount)` stack-spending (self-fuel in the Item pipeline, opponent-fuel in the Combat-manager spawn path) + an **evasion** fizzle seam (`causes_evasion` → `Delivery.evaded`, a whiff with a reason, distinct from silence/`gate` = inert); and **mid-fight roster changes** Cap 3 — the `CombatManager` **two-roster** model (player side = run actor + run-scoped `allies` + combat-scoped `_player_tokens`; enemy side = `enemies`) with `add_actor` (combat-scoped summon), `register_ally` (run-scoped mid-fight ally), `Delivery.Kind.SUMMON`, and scope-aware teardown — so **allies support both run and combat scope** (#22). All placeholder content; the mechanisms are wired.

- **Content scaffolding built (2026-06-07, 217 tests):** content ids are now **string ids** (#23, amended from int enum), `src/content/` is reorganized into **kind-grouped subdirs**, a **minimal character system** (`CharacterDef`/`CharacterCatalog`) drives the start kit + a **per-character draft pool** (#27), and a shared **colorless pool** (empty by default) is appended at draw.

- **Multi-actor combat view + pause-anytime + mid-fight ally wiring — built (2026-06-08, 223 tests):** the framed `CombatView` now renders a **board strip per actor** (every enemy in the right column, the player's prominent board bottom-left, each run-scoped ally / combat-scoped summon token in a column beside it — reading the CM rosters each frame, so mid-fight summons appear as they spawn; `actor_pos` resolves each to its own strip) (#4); **pause is available at any point** in a live run (a run-screen gate, the menu's full-rect catcher blocking the board underneath) (#8); `RunManager.add_ally` registers a run-scoped ally into the **live** fight mid-combat (#6); plus a review pass — catalog `get_def` id-guards (an unknown id `push_error`s instead of a null-deref crash), a periodic-status-on-item guard, and `_payload_from_effect` / `throw_consumable` summon+consume field parity.

- **Ally acquisition + character-select + settings + combat-view relayout (2026-06-09):** a recruit Event grants a run-scoped ally (4-slot cap); a **character-select** screen + a **settings** screen (audio-volume `Prefs` persisted to `user://`); the combat view relaid out **corridor-forward** (corridor large top-left, an `enemy_hud` pinned above each occupant sprite, player portrait + HP centre-bottom, its board a column down the right edge, allies in flanking slots) + a **compact windowed map**.

- **Status system refactored + first Spore Druid weapons (2026-06-10, #29):** statuses are now polymorphic `StatusEffect` classes (string-id, per-application duration, one file per status) behind a stateless facade — `StatusDef`/`StatusCatalog`/the `Type` enum removed; the beat model went CHOICE→ROLL (beats auto-roll combat/event, the choice layer dormant); the Spore Druid gained its first common attacks (a DPS = cooldown + 3 curve) + Wilt Frond; and every gameplay/UI colour + shared draw-const was centralized into `Colours` / `Consts`. **251 GUT tests green.**

- **Next: the deferred content push** — scale the per-character item / enemy / encounter pools, the boss signature mechanics + the Spore Druid spore content, then a real `tune` pass.

- **Full-resolution art, palette clamp and 3D corridor prototype — built (2026-09-14, 379 tests,** [`../plans/full_res_art_palette_clamp_3d_corridor.md`](../plans/full_res_art_palette_clamp_3d_corridor.md)**):** the F1 [debug panel](../systems/debug_panel.md) autoload; the full-screen [palette clamp](../systems/palette_clamp.md) with the owner's palettes copied into `assets/palettes/`; `axis_scale` moved to `CorridorRenderer` and implemented per renderer; `CombatCorridor` hosts the renderer chosen in the panel; [`Corridor3D`](../systems/corridors/corridor_3d.md) with code-built and kit piece sources; painted sample monsters as the default enemy images. Seeded autotest unchanged. The kit itself is not bought yet.

- **3D corridor lighting, enemy cut-outs and palette screenshots — built (2026-09-14, 386 tests):** `Corridor3D`'s omni light replaced by `corridor_light.gdshader`, a material overlay with exports for range, falloff, banded steps and flicker, so the corridor fades to black before its geometry ends (the owner is still choosing these values); enemy images darken with that light through `CorridorRenderer.enemy_brightness`; `tools/cut_out_monsters.gd` writes the painted samples with transparent backgrounds to `assets/monsters/cut_out/`, now the default; `DebugPanels` start-up arguments `--corridor=` and `--monster-image=` for screenshotting real fights; greyscale-and-red `trollslottet` palettes (6, 8, 12 colours, placeholder names). Seeded autotest unchanged. Open: an intermittent missing clamp in screenshots ([palette_clamp.md](../systems/palette_clamp.md#known-issue)).

- **World palette clamp on the combat corridor — built (2026-09-14, 388 tests,** [`../plans/separate_palettes.md`](../plans/separate_palettes.md)**):** the palette matching moved into `palette_clamp.gdshaderinc`; `world_clamp.gdshader` on the `CombatCorridor` container clamps only the corridor walls and enemy images; a "World palette" debug panel choice and `--world-palette=`. `Corridor3D.light_mode` can switch to four `OmniLight3D` wall lights (darker corners; enemy images keep the shader formula), chosen in the debug panel or with `--corridor-light=`. The owner answered the plan's open questions (recorded in the plan). Seeded autotest unchanged.

- **3D corridor lit by one light at the camera (2026-09-15, 388 tests):** `corridor_light.gdshader` and the wall lights are removed; [`Corridor3D`](../systems/corridors/corridor_3d.md#light) is lit by a single `OmniLight3D` node in `corridor_3d.tscn` (exports `light_range`, `light_energy`, `light_attenuation`, flicker), with no ambient light. Screenshots in a real fight showed the wall lights and the centre light looking almost the same, and the owner chose the centre light for simplicity. `light_bands`, `angle_shading`, `measure_along_corridor`, `CodeBuiltPieceSource.unshaded`, the F1 "3D light" choice and `--corridor-light=` are gone; `light_falloff` now only shapes enemy image brightness. The owner set the light's defaults to a 20m range and attenuation 1.5, which gives a gradual fade instead of the abrupt edge at the old 4m range; sections are built out to the range. Seeded autotest unchanged.

- **3D corridor only, enemies as lit `Sprite3D` nodes (2026-09-15, 390 tests, decision #36):** `CorridorScaled`, `CorridorPerspective`, `CorridorRenderer` (merged into [`Corridor3D`](../systems/corridors/corridor_3d.md)), `sharp_bilinear.gdshader`, `corridor_panel.tscn` and the `corridor_panel_example` scene are removed, with their docs (`common.md`, `scale_and_place.md`, `perspective_quad.md`). Enemies are `Sprite3D` nodes under the corridor's `Enemies` node: shaded, alpha scissor (default threshold picked from screenshots), sized to `ENEMY_PAINTED_HEIGHT` at depth 0; HUD anchors come from unprojecting the sprite top. `CombatCorridor.set_enemies(actors)` replaces `set_enemy_count`, so each enemy keeps its own sprite and image when another enemy dies (before, the rightmost sprite was always removed). Removed: `axis_scale`, `enemy_brightness`, `enemy_arrived_brightness`, `light_falloff`, the F1 Corridor and Enemy images rows, `--corridor=`, `ENEMY_FULL_SCALE` and the pixel sprite path, and the testbed's renderer cycling and blur slider. Enemy size and HUD position at arrival match the previous build in screenshots. Seeded autotest unchanged.

- **Rakkas as the interface font, with a debug font choice (2026-09-15, 398 tests):** the owner compared 24 fonts in screenshots of a fight, the item tooltip and the title screen, and chose Rakkas (`assets/fonts/rakkas.ttf`) for `Prefs.FONT_PATHS` VECTOR, replacing the engine's built-in Open Sans. The other shortlisted fonts (Alegreya SC, Cinzel, Eczar, Germania One) are in `assets/fonts/candidates/`, selectable in a new F1 "Font" dropdown or with `--font=` ([ui_theme.md](../systems/ui_theme.md#font-candidates)). `MapStrip` and `VfxDriver` drew text with `ThemeDB.fallback_font`, so the map's act label and the damage numbers ignored the chosen font; they now use the theme's default font.

- **Interface palette and background wear (2026-09-15, 407 tests):** the [interface palette](../systems/interface_palette.md) loads a `.gpl` file whose colour names match `Colours` variables (now static variables) and recolours the theme's font colours, images and panel colours by brightness; colours that were typed into scenes (health bars, portraits, the potion swatch, screen backgrounds, the pause panel, tooltip rarity) now come from `Colours` through `NamedColourRect` and theme variations (`LabelDim`, `PanelPause`). Chosen in F1 or with `--ui-palette=`; `ui-default.gpl` lists every name. Effect colours stay shared between item badges and projectiles (owner). [Background wear](../systems/background_wear.md) draws specks, scratches, rubbed edges and creases on each screen's `ScreenBackground` in two palette colours, from a worn record sleeve the owner liked; settings in the F2 look panel, look files and `--background-set=`. With no palette and no wear, screenshots match the previous build. The seeded autotest was not run; nothing here touches game logic.

- **Background specks tuned from screenshots (2026-09-15, 407 tests):** specks default to a lower density, gather into clumps, vary in size and mix dark and light colours. A mottled texture and faint flecks were tried and removed at the owner's request; the owner kept the rubbed edges and creases and wants specks only if sparse.

- **Background faded areas (2026-09-15, 407 tests):** a new Background Faded Areas group in the [background wear](../systems/background_wear.md) shader, from a second record sleeve the owner linked: a few large, soft, upright patches where the background blends towards the dark wear colour, with fine grain inside. It is the one blended wear effect (the owner chose a smooth blend over dithered steps) and defaults to subtle. The owner asked for about a quarter of the first coverage and picked a low amount from screenshots, then asked for the wear to be on by default: faded areas, specks, rubbed edges and two creases now start on. Scratches were shown in screenshots and removed from the shader at the owner's request. No new palette colour. Nothing touches game logic.

- **Print frame and the F3 print panel (2026-09-15):** looks for making the combat screen feel printed on the same sheet as the worn background, each a switch in a new F3 [print panel](../systems/print_frame.md), which also takes over the background wear sections from F2: a rough border around the corridor (`UI_BORDER`), the background wear drawn over the corridor, a worn corridor edge, and Background Folds (straight folds that can line up with the corridor, from the owner's folded-paper idea). `PrintFrame` moves the corridor in by a corridor margin, so the corridor is now smaller on every side by default. The wear code moved into `print_wear.gdshaderinc` so the background and the corridor overlay share it. Two placeholder two-ink red look files. The look panel now skips groups with no settings. F2 and F3 keep separate saved looks: F2 saves the corridor look to `assets/looks/`, F3 saves print looks (background wear, border, overlay, margin) to `assets/print_looks/` (owner). Faded areas halved again in size and amount (owner). Nothing touches game logic.

- **Full-screen palette clamp removed (2026-09-16):** the separate world and interface palettes replace it (owner). The F1 "Palette" list, `ClampLayer`, `palette_clamp.gdshader`, `set_palette()` and `--palette=` are gone; `palette_clamp.gdshaderinc` stays for the world clamp. The `[`, `]` and `'` keys now act on the World palette list, and colour matching and dithering apply to the world clamp only. Nothing touches game logic.

- **Interface palette keys and palette combos (2026-09-16):** `;` and `'` step through the interface palettes and `\` now shortlists the world palette (owner). The F1 panel saves and loads palette combos (world palette, interface palette, colour matching, dithering) in `assets/palette_combos/`, and a "Load at start-up" choice loads one when the game starts, except in headless, `--shot` and palette-argument runs; `--palette-combo=` loads one for screenshots. An interface palette now updates what is already on screen: `NamedColourRect` listens to `DebugPanels.interface_palette_changed`, and statuses in the current fight are recoloured. Nothing touches game logic.
